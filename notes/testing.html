What is Mockito?

Mockito creates mock objects to stub collaborator behavior in unit tests — @Mock, when(...).thenReturn(...), verify(...).

Usage

Mock repositories and external APIs; test service layer without Oracle/Kafka.

@InjectMocks wires the class under test.
Mock vs Spy.

A mock is fully fake; a spy wraps a real object and can stub specific methods while calling real code for others.

When to use

Mock: pure unit test, no real side effects.

Spy: partial real behavior (e.g. spy on ArrayList) — use sparingly; prefer mock for clarity.

What is test coverage?

Test coverage measures which lines/branches execute during tests — JaCoCo in Maven/Gradle reports percentage.

Practice

Aim for high coverage on domain logic; 80%+ on critical payment modules.

Coverage is a guide, not proof of quality — assert behavior, not just lines.

What is assertion?

An assertion checks an expected condition in a test — fails the test immediately if wrong.

Examples
assertEquals(expected, actual); assertThrows(InsufficientBalanceException.class, () -> service.debit(...)).

AssertJ fluent: <code>assertThat(balance).isEqualByComparingTo("100.00")</code>.

How do you test service layer?

Test the service layer with @ExtendWith(MockitoExtension.class) — mock repositories/clients, invoke service method, assert result and interactions.

Example

Mock <code>AccountRepository</code>; when find returns account; call <code>transfer()</code>; verify save called twice.

Test edge cases: insufficient balance, invalid state transitions.

How do you test controller layer?

Test controllers with @WebMvcTest or MockMvc — mock service layer, send HTTP request, assert status and JSON body.

Example
mockMvc.perform(post("/payments").content(json)).andExpect(status().isCreated()).

Validate validation errors return 400 with field messages.

How do you test repository/database layer?

Repository tests use @DataJpaTest with in-memory H2 or Testcontainers Oracle — verify queries return correct entities.

Approach

Insert test data; call repository method; assert results.

Testcontainers gives production-like SQL dialect for complex native queries.

How do you mock external API calls?

Mock external APIs with MockWebServer, WireMock, or Mockito stub of RestTemplate/WebClient wrapper.

Practice

Return canned JSON for success/timeout/500; verify retry logic.

Contract tests (Pact) for partner API compatibility.

How do you test exceptions?

Use assertThrows or assertThatThrownBy to verify the correct exception type and message for invalid input.

Example
assertThrows(InsufficientBalanceException.class, () -> paymentService.debit(account, amount)).

Also test that global handler maps to correct HTTP status in MVC tests.

What is integration testing?

Integration testing verifies multiple components together — real Spring context, DB, messaging — slower than unit tests.

Spring
@SpringBootTest with Testcontainers; test full flow from API to DB.

Use dedicated test profile and clean data between tests.

Unit test vs integration test.

Unit tests are fast and isolated with mocks; integration tests use real wiring (DB, context) and catch configuration/SQL issues.

Pyramid

Many unit tests, fewer integration tests, few E2E/UI tests.

CI runs unit on every commit; integration on PR or nightly.

What is regression testing?

Regression testing re-runs existing tests after a change to ensure nothing broke — automated suite in CI before release.

Banking

Full regression before UAT sign-off and after vendor patches.

Include payment, interest, and reconciliation scenarios.

What is UAT?

UAT (User Acceptance Testing) is business-owned validation that the system meets requirements before go-live.

Process

Business writes test cases from BRD; executes on UAT environment; signs off or logs defects.

Distinct from SIT — focuses on business outcomes, not technical integration only.

What is test case and test plan?

A test case is steps + expected result for one scenario; a test plan defines scope, environments, schedule, and entry/exit criteria.

Banking example

Test case: NEFT transfer with insufficient balance → expect rejection message X.

Test plan: all payment modules in SIT week 2; exit criteria 95% pass rate.

How do you write unit test for private methods?

Do not test private methods directly — test through public API; if untestable, refactor extraction to package-visible collaborator.

Alternatives

Reflection-based tests are brittle — avoid.

Extract pure function to testable utility class.

How do you test asynchronous code?

Test async code with @Async test config, CompletableFuture.get(timeout), Awaitility, or @TransactionalEventListener with test event publisher.

Kafka

Embedded Kafka or Testcontainers; consume test topic and assert message content.

How do you test message queue consumers?

Publish test message to queue/topic (or mock channel), invoke listener, assert DB side effects and ack behavior.

Tools

Spring <code>@JmsListener</code> tests with embedded broker; Kafka Testcontainers.

Verify DLQ path on processing failure.
