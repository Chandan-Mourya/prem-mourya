What is JavaScript?

JavaScript is a dynamically typed, event-driven, prototype-based scripting language that runs in the browser (and Node.js server-side) to make web pages interactive.

Key features

Single-threaded with event loop; non-blocking I/O via callbacks, Promises, async/await.

Prototype-based inheritance; first-class functions; closures; dynamic typing.

Banking use

Internet banking portal: form validation, REST API calls for balance inquiry, dynamic transaction table rendering.

`var` vs `let` vs `const`.

var is function-scoped and hoisted; let is block-scoped; const is block-scoped with a binding that cannot be reassigned.

var

Function scope: accessible outside if block — bug-prone. Hoisted with undefined initial value.

let / const

Block scope ({}): only accessible within the declaring block. let allows reassignment; const does not.

const for objects/arrays: the reference is constant but contents can still be mutated — use Object.freeze() for deep immutability.

Now coming to conclusion.

Prefer const by default; use let only when reassignment is needed; avoid var in modern JavaScript.

What is closure? must

A closure is a function that remembers variables from its outer scope even after the outer function finished.

Now coming to use.

Callbacks, event handlers, encapsulation in JavaScript.

What is promise?

A Promise represents the eventual completion (or failure) of an asynchronous operation and its resulting value.

States

Pending → Fulfilled (resolve called) → value available via .then(). Pending → Rejected (reject called) → error via .catch().

Usage

fetch('/api/account/balance').then(res => res.json()).then(data => updateUI(data)).catch(err => showError(err));

Now coming to conclusion.

Promises replaced callback hell; async/await syntactically wraps Promises for sequential-looking async code.

Promise vs async/await.

Promises use .then()/.catch() chaining; async/await is syntactic sugar over Promises, enabling sequential async code without chaining.

async/await

async function getBalance(accountId) { const res = await fetch('/api/balance/'+accountId); return await res.json(); }

Error handling with try/catch instead of .catch() — more readable for sequential async flows.

When to use

async/await for sequential dependent async calls; Promises with Promise.all() for parallel async calls.

Now coming to conclusion.

async/await is the modern standard — use Promise.all([...]) for concurrent async operations.

What is event loop?

The event loop allows JavaScript's single thread to handle asynchronous operations by continuously checking the call stack and processing callbacks from the task queue.

Mechanism

Call stack: executes synchronous code. Web APIs (setTimeout, fetch): handle async ops outside the stack.

Task queue (macrotask): setTimeout, setInterval callbacks. Microtask queue: Promise .then() callbacks — processed before next macrotask.

Event loop: when call stack is empty, processes microtasks first (all of them), then one macrotask.

Now coming to conclusion.

Microtasks (Promise.then) always execute before macrotasks (setTimeout) — understand this for correct async behavior.

What is DOM?

The DOM (Document Object Model) is a tree representation of an HTML document that JavaScript can read and manipulate to dynamically update the page.

Structure

document.getElementById('balance'), querySelector('.account-row') — access nodes.

node.textContent = '₹50,000'; node.classList.add('highlight'); node.remove() — manipulate nodes.

Banking

After balance API call: document.getElementById('balance').textContent = formatCurrency(data.balance);

Now coming to conclusion.

Excessive DOM manipulation is slow — batch updates or use a framework like React/Angular for efficient rendering.

What is Angular?

Angular is a TypeScript-based full-featured SPA framework by Google offering two-way data binding, dependency injection, routing, forms, and HTTP client out of the box.

Key concepts

Component: @Component with template, styles, and logic. Module: @NgModule groups related components.

Two-way binding with [(ngModel)]; event binding (click)='handler()'; property binding [value]='expr'.

Banking

Internet banking portals built in Angular: lazy-loaded modules for Accounts, Loans, Payments — each loaded on demand.

Now coming to conclusion.

Angular is opinionated — enforces structure which suits large banking teams with multiple developers.

Angular component vs service.

An Angular component handles UI rendering and user interaction; a service contains reusable business logic, HTTP calls, and shared state.

Component

@Component: template (HTML), styles (CSS), class (event handlers, lifecycle hooks).

Responsible for presentation only — should delegate data fetching to services.

Service

@Injectable({ providedIn: 'root' }): singleton service; injected into components via constructor.

AccountService.getBalance(accountId): Observable<Balance> — wraps HTTP call, reusable across multiple components.

Now coming to conclusion.

Separation of concerns: components are dumb-ish views; services hold business logic and API calls.

What is dependency injection in Angular?

Angular's dependency injection (DI) system creates and provides service instances to components, managed by the Injector — eliminates manual object creation.

How it works

Register provider: @Injectable({ providedIn: 'root' }) creates a singleton at app level.

Inject: constructor(private accountService: AccountService) — Angular Injector provides the instance.

Scope

Root: one instance for the entire app. Module: one per module. Component: new instance per component.

Now coming to conclusion.

Angular DI mirrors Spring DI — both manage singleton beans/services with constructor injection preferred.

What is React?

React is a JavaScript library by Meta for building UI from declarative components — using a virtual DOM for efficient rendering updates.

Key concepts

Component: function or class returning JSX (HTML-like syntax in JS). Props: immutable inputs. State: mutable internal data.

Virtual DOM: React diffs the VDOM tree and only updates real DOM nodes that changed — efficient rendering.

Banking

Mobile banking web apps (React Native for native apps): transaction list, fund transfer form, account dashboard.

Now coming to conclusion.

React is a library (just UI); add React Router for navigation, Redux/Zustand for state management.

What are props and state?

Props are immutable inputs passed from parent to child component; state is mutable internal data that triggers re-rendering when updated.

Props

Read-only in the child; parent-to-child data flow. <AccountCard accountId={id} balance={balance} />

State

const [balance, setBalance] = useState(0); — calling setBalance() triggers component re-render.

State changes are batched in React 18; async setState does not immediately reflect in the same render cycle.

Now coming to conclusion.

Lift state up to the nearest common ancestor when multiple siblings need to share data.

What is virtual DOM?

The Virtual DOM (VDOM) is React's in-memory representation of the UI; on state change, React diffs the new VDOM with the previous and applies only the minimal real DOM changes.

Process

Render: React creates new VDOM tree. Diffing: compare new vs old VDOM (O(n) algorithm with heuristics).

Reconciliation: apply only the changed nodes to the real DOM — avoids expensive full DOM updates.

Why it matters

Real DOM manipulation is slow; VDOM diffing in memory is fast — React minimizes DOM writes.

Now coming to conclusion.

VDOM is an optimization detail — understand it for performance debugging; don't over-engineer around it.

What are React hooks?

React hooks (React 16.8+) let functional components use state, lifecycle, context, and refs — without class components.

Core hooks

useState: component state. useEffect: side effects (data fetch, subscriptions) — runs after render.

useContext: consume context. useRef: mutable ref without re-render. useMemo/useCallback: performance optimization.

Banking

useEffect(() => { fetchBalance(accountId).then(setBalance); }, [accountId]) — fetch on accountId change.

Now coming to conclusion.

Rules of hooks: only call at top level (not inside conditions); only call from React functions — enforced by linter.

What is Knockout.js?

Knockout.js is a MVVM JavaScript library providing declarative bindings, observables, and computed values for automatic UI updates when data changes.

Key concepts

observable(): ko.observable(balance) — when value changes, bound UI elements update automatically.

Declarative binding: data-bind='text: balance, css: {negative: balance() < 0}' in HTML.

Banking context

Some legacy FLEXCUBE web screens use Knockout.js for the front-end — important to know for FLEXCUBE customization.

Now coming to conclusion.

Knockout is mature and stable but largely superseded by Angular/React in modern projects.

What is two-way data binding?

Two-way data binding automatically synchronizes the UI (view) and the application data (model) in both directions — UI change updates model; model change updates UI.

Angular example

[(ngModel)]='accountName': typing in the input field immediately updates accountName variable; changing accountName in code updates the input.

React difference

React uses one-way data flow: state → UI; UI events → event handlers → setState() → re-render. More predictable but more verbose.

Now coming to conclusion.

Two-way binding simplifies forms but can make data flow harder to trace in large banking forms.

How do you call REST API from frontend?

Frontend REST API calls use fetch() (native) or Axios (popular library), with JWT in Authorization header and error handling for network and HTTP errors.

Using fetch

fetch('/api/accounts/'+id, { headers: { 'Authorization': 'Bearer '+token } }).then(r => r.json()).then(setData).catch(setError)

Using Axios

axios.get('/api/accounts/'+id, { headers: { Authorization: 'Bearer '+token } }).then(r => setData(r.data))

Axios interceptors: add token to all requests automatically; handle 401 globally to redirect to login.

Now coming to conclusion.

Always handle 401 (token expired) globally — redirect to login without requiring individual API call handlers to manage it.

How do you handle form validation?

Form validation is handled with HTML5 built-in constraints, JavaScript validation logic, or library validators — providing immediate feedback before API submission.

Approaches

HTML5: required, min, max, pattern attributes on input — browser validates before submit.

Angular: Reactive Forms with Validators.required, Validators.min(1), Validators.pattern() on FormControl.

React: validate in onChange handler; show error message if invalid; disable submit button until form is valid.

Banking

Transfer amount: positive number, ≤ daily limit. Account number: exactly 16 digits. IFSC: pattern [A-Z]{4}0[A-Z0-9]{6}.

Now coming to conclusion.

Always validate on both client (UX) and server (security) — never rely solely on frontend validation.

How do you handle authentication token in frontend?

JWT tokens should be stored in memory (JS variable) for SPA security, or httpOnly cookies — never in localStorage due to XSS vulnerability.

Storage options

httpOnly Cookie: set by server; not accessible by JS — immune to XSS. Use SameSite=Strict and Secure flags.

Memory (JS variable): lost on page refresh; combine with silent token refresh via refresh token in httpOnly cookie.

Usage

Axios interceptor: config.headers.Authorization = 'Bearer ' + getToken() — adds to every request automatically.

On 401 response: use refresh token to get new access token; retry original request.

Now coming to conclusion.

localStorage is convenient but unsafe for tokens — XSS can steal tokens and impersonate the user in banking.

How do you debug UI issue?

UI issues are debugged using browser DevTools: Console for JS errors, Network tab for API calls, Elements tab for DOM inspection, and Sources for breakpoints.

DevTools workflow

Console: check for JS exceptions, unhandled Promise rejections, CORS errors.

Network: inspect API request (URL, headers, payload) and response (status, body) — compare with API contract.

Sources: set breakpoints in JS code; inspect variable values at each step.

Banking scenarios

Wrong balance displayed: Network tab shows API returned correct value → bug is in frontend rendering/formatting logic.

Form submit does nothing: Console shows validation error or CORS block — check error and fix.

Now coming to conclusion.

Always check Network tab first — most UI bugs are either wrong data from API or incorrect rendering of correct data.
